# NexaFlow Database

> Phase 1 — Foundation schema. Subsequent phases add tables.

## 1. Engine

- **PostgreSQL 16** (or newer).
- **Provider:** `Npgsql.EntityFrameworkCore.PostgreSQL` 10.0.0.
- **Naming:** snake_case for tables, columns, indexes, and constraints
  (via `EFCore.NamingConventions`).
- **Primary keys:** `uuid` (Guid) — generated by the application.
- **Timestamps:** `timestamptz` (UTC throughout — never naive `timestamp`).

## 2. Phase 1 Schema

The Phase 1 migration (`20260929173949_InitialCreate`) creates three
tables — the minimum to support tenant resolution (Phase 2) and
cross-tenant isolation tests (Phase 3):

### 2.1 `users`

organizations via `organization_members`.

| `email_normalized` | `text` | lowercase normalized; unique |

| `password_hash` | `text` | BCrypt encoded string (max 128) |
| `email_verified` | `bool` | |
| `email_verified_at_utc` | `timestamptz` | nullable |

**Indexes:**

### 2.3 `organization_members`

The membership link between `users` and `organizations`. **Tenant-scoped**
(implements `ITenantEntity`).

| Column | Type | Notes |
|---|---|---|
| `id` | `uuid` | PK |
| `organization_id` | `uuid` | FK→organizations(id), tenant discriminator |
| `user_id` | `uuid` | FK→users(id) |
| `role` | `int` | OrganizationRole enum: Owner=1, Admin=2, Member=3, Viewer=4 |
| `is_active` | `bool` | false for pending invitations |
| `invitation_token_hash` | `text` | nullable; hashed for Phase 3 |
| `accepted_at_utc` | `timestamptz` | nullable |
| `created_at_utc` | `timestamptz` | |
| `updated_at_utc` | `timestamptz` | |
| `created_by_user_id` | `uuid` | nullable |
| `updated_by_user_id` | `uuid` | nullable |

**Indexes:**
- `uq_organization_members_organization_id_user_id` — unique on

- `ix_organization_members_user_id` — secondary index on `user_id`
  for "list this user's memberships" queries.

## 4. Multi-Tenancy Enforcement at the Database Layer

Per [ADR-004](decisions/ADR-004-multi-tenancy.md):

1. Every tenant-owned table has an `organization_id` column with
   appropriate indexes.
2. EF Core global query filter scopes all reads to the current tenant.
3. The `ApplicationDbContext.SaveChangesAsync` override rejects any
   tenant-owned entity whose `OrganizationId` does not equal the
   resolved tenant id at insert time.
4. `OrganizationId` is immutable after insert (the DbContext rejects
   mutations of the column).
5. Unique indexes include `organization_id` where appropriate
   (e.g., the membership `(organization_id, user_id)` pair) so
   cross-tenant duplicates cannot persist even if higher layers have
   a bug.

## 5. Migrations

Phase 1 includes the `InitialCreate` migration. Apply with:

```bash
# Local dev (using docker compose)
docker compose up -d postgres
cd src/NexaFlow.Api
ASPNETCORE_ENVIRONMENT=Development \
  dotnet ef database update \
    --project ../NexaFlow.Infrastructure/NexaFlow.Infrastructure.csproj \
    --startup-project NexaFlow.Api.csproj
```

In production, migrations are applied as a separate init step (not on
container start) — see Phase 11 CI/CD.
